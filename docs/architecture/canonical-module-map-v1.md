## 收敛规则

1. 所有 API / Server Actions / 后台任务必须在服务端执行授权；不能依赖隐藏按钮或客户端角色字段。
2. 路由/API 只调用规范领域模块，不复制权限判断、金额公式、状态机或库存逻辑。
3. 兼容适配必须标记弃用期限，并增加调用方迁移测试；不得长期保留两套可独立修改的规则。
4. 所有资金写操作必须经过事务服务、幂等键和双重记账；领域纯函数只负责校验，不直接改余额。
5. 库存预留、支付确认、退款冻结/完成、商户结算和提现必须在数据库事务中完成，并覆盖重复请求及并发冲突。
6. 只有在调用方迁移、测试通过且无引用后，才删除重复文件；本次仅确定映射，不盲删尚未审阅的调用方。

## 当前风险与待办

- 已在集成分支新增 `src/lib/security-config.ts` 并由根目录 `instrumentation.ts` 调用：生产 Node.js 服务启动时校验 AUTH_SECRET，缺失或 UTF-8 长度不足 32 字节即阻止启动；错误只显示变量名和错误码，不显示密钥值。
- 当前集成分支仍是脚手架/领域层，不存在可证明完整的登录、验证码、数据库事务、支付、退款、提现或文件授权闭环。
- PR #2–#7 保持草稿，不直接合并；PR #8 是唯一集成入口。
- 数据库 PR #10 仅为设计草案；即使 CI 通过，也必须在隔离 PostgreSQL 15 测试库验证迁移、约束、并发和回滚。

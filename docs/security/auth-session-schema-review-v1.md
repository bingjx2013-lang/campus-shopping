# 登录、验证码与会话数据结构审查 v1

日期：2026-10-31
审查分支：`work/database-review-v1`
对象：`database/migrations/0002_campus_shopping_full_schema_v1_draft.sql`
状态：静态 SQL 审查；未连接 PostgreSQL，未执行迁移。

## 已有基础表

当前草案已包含：
- `users`：手机号唯一字段、密码哈希字段、账号状态和用户类型。
- `auth_sessions`：用户 ID、刷新令牌哈希、设备指纹哈希、IP、User-Agent、过期时间和撤销时间。
- `verification_codes`：用途、主体、验证码哈希、过期时间、消费时间和尝试次数。
- `login_events`：成功/失败事件、原因码、IP、设备哈希和时间。
- `audit_logs`：操作者、动作、目标、前后数据、原因和 IP。
- 管理员角色/权限及审批记录表。

这些是数据结构基础，不代表已经实现可运行的认证功能。

## 主要缺口与风险

### 1. 用户凭据
- `password_hash` 目前只是无约束文本列；需规定只接受现代密码哈希算法的编码结果（推荐 Argon2id），禁止明文、可逆加密或快速通用哈希。
- 手机号需在服务层标准化为 E.164 后再唯一校验；历史空值和重复数据需要上线前检查。
- 登录失败锁定策略、密码重置和凭据变更后的会话撤销尚未形成完整规则。

### 2. 验证码
- 当前有哈希、过期、消费和尝试计数，但未见数据库约束或事务流程保证验证码只能成功消费一次。
- 缺少明确的发送冷却、手机号/IP/设备多维速率限制、最大错误次数锁定和重发失效策略。
- `subject + purpose` 需要统一规范；登录、注册、找回密码和新设备验证必须隔离用途。
- 验证码应使用密码学安全随机数，短有效期（项目已确认 2 分钟），使用后原子标记消费；日志不得记录验证码或其可重放材料。

### 3. 会话与设备
- 目前只存刷新令牌哈希和单一撤销时间；缺少令牌族/轮换链、上次使用时间、撤销原因、设备验证状态及重放检测所需信息。
- 需定义短期访问凭证与长寿命刷新令牌的职责；刷新令牌必须轮换，旧令牌重放时撤销同一令牌族。
- 新设备必须完成手机号验证码验证（项目已确认验证码有效期 2 分钟）；不能仅凭客户端设备指纹认定可信设备。
- 应支持单设备登出、全设备登出、账号锁定后撤销会话、密码重置后撤销会话。

### 4. 数据库约束和并发
- 为会话用户、有效期、撤销字段增加一致性约束和查询索引。
- 对验证码消费采用事务内条件更新（未消费、未过期、尝试次数未超限）并检查受影响行数；并发请求只能一个成功。
- 验证码请求需要限流记录或独立限流存储；仅依靠应用进程内计数不适用于多实例。
- 对手机号归一化、账号恢复和重复学生账号检测设计并发安全的唯一性/人工审核流程，不能通过错误提示泄露账号是否存在。

## 必须完成的测试

1. 验证码恰好 120 秒到期边界、过期后拒绝、用途错配拒绝。
2. 同一验证码并发消费，必须恰好一个请求成功。
3. 达到最大尝试次数后锁定；重发后旧验证码失效。
4. 手机号/IP/设备发送速率限制；不同实例之间限流一致。
5. 新设备未经验证不能创建完整会话；设备指纹伪造不能绕过验证码。
6. 刷新令牌轮换成功；旧令牌重放撤销令牌族。
7. 单设备/全设备登出、账号锁定、密码重置后旧会话全部失效。
8. 不同用户会话隔离；修改请求中的 userId 不能切换身份。
9. 日志和错误响应不包含密码、验证码、刷新令牌或敏感身份信息。
10. PostgreSQL 并发事务测试、迁移回滚测试和索引查询计划检查。

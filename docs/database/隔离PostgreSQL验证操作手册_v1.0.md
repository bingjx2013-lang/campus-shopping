# 隔离 PostgreSQL 验证操作手册 v1.0

> 仅用于一次性、可销毁的测试数据库。严禁连接生产库、真实用户数据或生产凭据。

## 1. 目标与边界

验证迁移文件：

1. `database/migrations/0002_campus_shopping_full_schema_v1_draft.sql`
2. `database/migrations/0003_inventory_finance_reliability_v1_draft.sql`

本手册不代表迁移已执行或通过。当前尚未连接任何数据库。

## 2. 测试环境要求

- PostgreSQL 15 或更高版本。
- 新建独立数据库，数据库名建议 `campus_shopping_migration_test`。
- 使用临时、最小权限测试账号；只授予该测试数据库所需的建表、建 schema、安装已允许扩展等权限。
- 不复用生产数据库 URL、生产密码、生产备份或真实个人信息。
- 测试前记录 PostgreSQL 版本、扩展可用性、执行角色和数据库名称。

## 3. 执行前安全检查

逐项确认：

- [ ] 连接目标确认为一次性测试数据库。
- [ ] 数据库中没有真实业务数据。
- [ ] 连接串不指向生产主机或生产数据库。
- [ ] 测试账号没有生产库权限。
- [ ] 已准备销毁测试数据库的方式。
- [ ] 已检查扩展 `pgcrypto`、`citext` 是否允许安装。

任一项无法确认，停止执行。

## 4. 建议执行顺序

在隔离测试数据库中分别执行并记录：

1. 查询 `SELECT version();`。
2. 执行 0002，保存完整 stdout/stderr 和退出码。
3. 检查 schema、表、索引、外键、约束数量。
4. 执行 0003，保存完整 stdout/stderr 和退出码。
5. 查询触发器、函数和索引是否存在。
6. 执行记账触发器专项测试。
7. 执行重复执行行为检查（当前迁移不是完整幂等脚本，预期重复执行可能失败；失败本身需记录，不可盲目重跑）。
8. 测试结束后销毁测试数据库，或保留无敏感信息的日志和结果。

建议通过 `psql -v ON_ERROR_STOP=1` 执行，使首个 SQL 错误立即令进程失败。每份迁移自身包含事务；不要在工具中再套入不兼容的外层事务。

## 5. 记账约束测试矩阵

| 场景 | 预期结果 |
|---|---|
| 在同一事务内先插借方、再插贷方，提交时借贷相等 | 成功 |
| 已过账分录借贷不相等 | 提交失败 |
| 已过账分录没有明细 | 提交失败 |
| 删除已过账分录中的一条明细导致不平衡 | 提交失败 |
| 将明细从已过账分录移动到另一分录，导致任一方不平衡 | 提交失败 |
| 未过账分录暂时不平衡 | 允许暂存；过账时必须校验 |

测试需使用专用 fixture 数据，并在每个用例后回滚或清理。不能在真实账务数据上测试。

## 6. 迁移之外仍需验证的关键服务

- 库存预占：SKU 行锁、可售库存原子扣减、幂等预占、超时释放、取消订单释放。
- 支付/退款：幂等键、重复回调、事务一致性、冻结不足时欠款处理。
- 结算/提现：冻结金额、双人审批、重复请求、支付渠道结果对账。
- Outbox：并发领取、租约超时、重试退避、重复消费去重。
- 认证：验证码 2 分钟过期、错误次数限制、发送限流、新设备校验、会话轮换与撤销。

# 校园购数据库完整设计说明 v1.0（草案）
> 范围：明德中英文学校永久单校校园购。PostgreSQL。配套 SQL 未在真实数据库执行，不是生产迁移。

## 原则
- 单校架构；学校、年级、班级字段只服务明德校内管理。
- 金额使用 numeric 定点数；订单商品、规格、单价和优惠分摊必须保存快照。
- 钱包、会计分录、库存流水、状态历史、审批与审计记录不可由后台直接改写。
- 支付、退款、结算、库存操作均需幂等键和事务保护。
- 密码只存强哈希；验证码只存哈希、用途、过期时间和尝试次数；新设备登录验证。
- 私有文件使用对象存储私有桶和短时授权 URL。

## 已确认规则落实
- 商家自由定义规格和值；SKU 独立库存；支持不限库存。
- 下单锁定价格快照；商品编辑不改历史订单；商品软删除。
- 多店铺总单拆子单，每店独立运费；同店允许分批发货。
- 下单后不能直接改数量；取消后重下。缺货由买家选择等待或退款。
- 部分退款按商品/数量/金额处理；商家拒绝后买家可立即申请平台介入。
- 售后期间暂停自动确认收货；退款成功不自动恢复库存。
- 应用内支付只用校园钱包（充值/提现除外）；订单收入先进入待结算；退款冻结/冲减待结算。
- 商家结算后进入商家校园钱包，再申请微信提现；商家不足额形成应收欠款并暂停相关结算。
- 复式记账；大额资金调整和异常退款双人审批；财务不能直接改余额。
- 费率、租金、额度、临时优惠均保留版本、生效时间、审批人和原因。
- 商家退出先停止新单，完成存量订单、售后和结算。
- 后台岗位分权；创始人最高权限单独保护并审计。

## 关键事务
1. 下单：按 SKU 固定顺序锁定行，检查并原子扣减/预占库存；写订单快照和流水；幂等键防重复。
2. 支付：锁买家钱包；同一事务写钱包流水、借贷分录和订单支付状态；重复请求不得重复入账。
3. 退款：建立售后案件并暂停自动收货；拒绝后可平台介入；退款先冻结商家待结算款，不足则记应收欠款并暂停结算；成功后记账，不自动回库存。
4. 结算：仅选未结算且无争议冻结订单；批次明细不可变；审核后转入商家钱包。

## 生产前必须补齐
- 库存预占/释放表及超卖并发测试。
- 事务 outbox、支付/退款/结算幂等实现。
- 提现申请、商家应收欠款、退款冻结分配、结算暂停关联表。
- 延迟约束触发器强制每张 journal entry 借贷相等。
- 余额锁定/派生策略；禁止直接修改余额。
- 密码哈希参数、验证码限流、新设备信任、会话轮换、找回和 MFA 方案。
- 与后端模型/API/原始数据库逐项核对；迁移、回滚、备份恢复测试。

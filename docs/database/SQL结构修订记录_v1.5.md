# PostgreSQL 草案结构修订记录 v1.5

日期：2026-10-31
目标文件：`database/migrations/0002_campus_shopping_full_schema_v1_draft.sql`
状态：仅静态设计草案，未执行。

## 本次已修改

1. **单校约束**：`school_config` 固定为单例记录（id=1），学校代码和名称固定为 MINGDE / 明德中英文学校，避免未来误插入第二所学校。
2. **学生监护人关系**：移除 `student_profiles` 上单一 `guardian_user_id`，新增 `student_guardians` 关联表，记录关系类型、主要监护人、核验时间和有效期，并对当前主要监护人建立唯一索引。
3. **钱包所有者引用**：移除不能建立普通外键的多态 `owner_id`，改为 user / merchant / platform 三种互斥所有者列，并分别建立真实外键和唯一约束；当前平台钱包币种限制为 CNY。
4. **会计事件幂等**：移除 `(source_type, source_id)` 全局唯一约束，允许同一业务对象发生支付、退款、结算和冲正等不同事件；新增 `event_type` 和唯一 `idempotency_key`，保留来源查询索引。
5. **商户身份与协议证据**：增加 `merchant_identity_verifications` 和 `merchant_agreement_signatures`，记录身份核验服务引用、签署人、签署身份、协议版本、内容哈希、签署时间、证据对象键和幂等键。不在此表存储原始证件号码。
6. **订单金额约束**：父订单增加非负金额、优惠不超商品金额，以及 `payable = item - discount + shipping` 的行内 CHECK。

## 仍需实现/验证

- 商户签署服务必须确认签署人确实是商户 owner 或有效 operator，并且引用的身份核验已验证、未过期；仅有表结构不等于完成实名签署。
- 监护人关系的创建、变更和撤销必须经过验证流程；唯一索引只保护当前主要监护人不重复。
- 钱包写入只能通过受限服务/存储过程和双重记账事务；应用不可自行修改余额。
- 父子订单金额、折扣分摊、发货累计量、退款上限、退款冻结和结算 hold 仍需要事务级约束及并发测试。
- 库存预留必须以原子条件更新或行锁执行；预留、支付、释放、超时回收都需要幂等。
- `journal_entries` 的唯一幂等键需要由每个业务事件稳定生成，重试必须复用同一个键。
- `0002` / `0003` 必须在一次性 PostgreSQL 15 数据库中从空库完整执行，验证触发器、索引、权限、并发冲突和回滚；目前未做此项验证。
- 该分支相对 main 可能落后一笔提交；建立合并 PR 前需先同步 main 并重新执行完整校验。

**不得将本修订视为生产就绪或直接在生产数据库执行。**

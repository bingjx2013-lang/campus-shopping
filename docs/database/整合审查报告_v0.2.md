# 校园购数据库整合审查报告 V0.2

## 项目边界
- PostgreSQL。
- 永久只支持明德中英文学校；不建设多学校租户隔离。
- 本轮将已确认的商品、订单、履约、售后、资金、权限、隐私和运营规则转为数据库要求。

## 重点设计要求
1. 库存区分实际库存、预留库存、可售库存和不限库存模式；库存变更必须有流水及幂等控制。
2. 订单保留商品、价格、地址、优惠、运费、费率和配送政策快照。
3. 多店铺订单拆分子订单；每批配送记录商品和数量明细。
4. 售后、部分退款、退款冻结/解冻、退款完成/失败及暂停自动确认收货必须有独立状态。
5. 钱包余额不能作为唯一账本；需要会计科目、分录头、分录行及借贷平衡校验。
6. 商家待结算、冻结、退款扣除、应收欠款、结算及提现必须可追溯。
7. 最高创始人授权不能仅靠普通角色字段赋予；应有强 MFA、独立授权、审批与审计。
8. 敏感信息查看、文件访问、数据导出和账号注销需要权限校验及审计。
9. 平台费率、租金、额度、特殊优惠和政策版本必须留存历史。

## 技术建议
- 主键 UUID；金额 NUMERIC；时间 timestamptz。
- 支付回调、退款、库存扣减、账务过账、消息投递设置唯一幂等键。
- 历史订单和资金记录采用追加记录/冲正，不覆盖历史事实。
- 库存预留、扣减和释放使用事务、行锁或原子更新。
- 会计过账通过数据库受控函数完成，并用延迟约束触发器确保借贷平衡。
- 文件使用私有对象存储和短时授权 URL。
